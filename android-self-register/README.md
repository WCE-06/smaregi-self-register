# セルフレジ Androidアプリ移行準備

既存のGitHub Pages顧客画面を、店舗専用Androidタブレット向けのネイティブアプリへ段階移行するための雛形です。WebViewで既存HTMLを包む方式ではありません。

## この雛形で完成しているもの

- Kotlin / Jetpack ComposeのAndroidプロジェクト構成
- 横画面固定のセルフレジUI
- 会員証 → 利用先 → 商品 → 内容確認 → 支払方法 → 決済確認 → 完了の状態遷移
- 取引IDを1取引の全処理で維持するReducer
- GAS・商品キャッシュ・FEBBRAIO・スマレジ売上確認を接続するRepository契約
- 状態遷移の単体テスト

現在の画面は開発プレビューです。実際の会員・商品・Pico W・スマレジへはまだ命令を送りません。

基準実機はPOCM-SM100（Android 12、1024×600）です。確認結果は`docs/DEVICE_PROFILE.md`に保存しています。

## 採用方針

- UI: Jetpack Compose
- 状態管理: ViewModel + StateFlow +単方向データフロー
- 商品・広告: 端末のローカルDBを表示上の正本にする
- 商品同期: バックグラウンドで15分ごと、失敗時は直近キャッシュを継続使用
- 会員確認・決済開始・売上確認: オンライン必須
- 秘密情報: APKやGitHubへ埋め込まず、店舗端末登録後に安全な設定APIから受け取る
- バーコードリーダー: HIDキーボード入力をActivityで受け、現在の状態に応じて会員／商品へ振り分ける
- 画面固定: ランドスケープ、キオスク運用を前提

## Android Studioで開く

`android-self-register`フォルダをAndroid Studioで開きます。初回はAndroid SDK 37と依存関係の取得が必要です。Gradle WrapperはAndroid Studioで生成してください。

## 実装順序

1. GASにAndroid用JSON APIを追加する
2. UIトークン付きJSONPを、端末認証付きHTTPS JSONへ変更する
3. 商品をRoomへ保存し、起動直後は必ずローカル商品を表示する
4. バーコードリーダー入力を接続する
5. 会員確認とFEBBRAIO料金コード取得を接続する
6. 既存ジョブキューへ会員・商品・決済操作を送る
7. スマレジ売上成立の確認APIを追加する
8. 「閉じる→新規取引」を実装する
9. 広告キャッシュと推薦ルールを追加する
10. キッチン注文APIを別モジュールとして接続する

## 移行完了条件

- 既存Web版と同じ3サービスを処理できる
- 商品同期に失敗しても前回商品が表示される
- 決済命令の二重送信が起きない
- スマレジ売上成立後だけ完了扱いになる
- 完了後にスマレジとAndroid画面が両方とも初期状態へ戻る
- 通信切断、Pico切断、アプリ再起動から復旧できる
- 顧客向け画面に内部エラーコードを表示しない
