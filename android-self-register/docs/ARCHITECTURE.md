# Androidセルフレジ構成

```text
Android顧客アプリ
├─ 会員証・商品バーコード入力
├─ 商品／メニュー／カスタマイズ表示
├─ 取引状態管理
├─ 商品・広告のローカルキャッシュ
└─ 顧客向け進捗・エラー表示
        ↓ HTTPS JSON
セルフレジAPI（当面はGAS）
├─ 端末認証
├─ 会員確認
├─ 商品差分同期
├─ FEBBRAIO利用照会
├─ 操作ジョブ登録・状態取得
├─ スマレジ売上確認
└─ 広告・営業時間・推薦ルール配信
        ↓
Windowsブリッジ → Pico W → BLE HID → スマレジiPad
```

## 1取引の状態

```text
MEMBER_SCAN
→ VERIFYING_MEMBER
→ SERVICE_SELECTION
→ PRODUCT_SELECTION
→ ORDER_REVIEW       商品登録をバックグラウンド開始
→ PAYMENT_SELECTION  商品登録完了を裏で待つ
→ STARTING_PAYMENT   ここだけ商品登録完了が必須
→ CONFIRMING_SALE    スマレジAPIで売上成立を確認
→ COMPLETED          閉じる→新規取引
→ MEMBER_SCAN
```

## オンライン必須とキャッシュ可能の境界

| 機能 | 方針 |
|---|---|
| 商品・画像・カテゴリー | ローカルキャッシュを即表示 |
| 広告 | ローカルキャッシュを再生 |
| 営業時間 | 最終同期値を表示し、注文確定時に再確認 |
| 会員確認 | オンライン必須 |
| FEBBRAIO利用照会 | オンライン必須 |
| 商品・決済ジョブ | オンライン必須、オフライン時は開始しない |
| 売上成立確認 | オンライン必須。遅延を失敗扱いしない |

## 複雑化を防ぐ境界

- Androidはスマレジの価格・税額を独自確定しない。
- FEBBRAIO料金は受付APIが返す完成品コードを使用する。
- キッチンの調理情報はスマレジ操作ジョブへ混ぜない。
- 推薦は承認済み広告の選択だけを行い、決済処理へ影響させない。
- 取引状態は`transactionId`で一意にし、全書き込みを冪等にする。
